# 需求文档（PRD）

> 校园跳蚤市场 · v1.0 ｜ 2026-11

## 1. 背景

高校每学期都有大量教材、数码、宿舍用品在毕业后或换季时闲置。现有渠道的问题：

| 渠道 | 问题 |
| --- | --- |
| 微信群 / QQ 群 | 消息刷得快，商品信息沉底；无法搜索、无法追踪状态 |
| 闲鱼等平台 | 面向社会，同城面交距离远；学生身份不可信；平台抽佣且流程重 |
| 宿舍楼公告栏 | 无图片、无价格、无法沟通 |

因此做一个**只服务本校**的二手交易站点：身份可验证、面交为主、流程轻。

## 2. 目标与非目标

**目标**

1. 让一件闲置从「发布」到「钱货两清」只需要一次对话，不需要跳转多个系统
2. 交易双方对「现在该谁操作」没有歧义
3. 校园身份可信，降低放鸽子和诈骗概率

**非目标（v1 不做）**

- 平台支付与资金托管（线下扫码转账 + 上传凭证替代）
- 物流对接（只做校内面交 / 自提 / 快递三种声明）
- 评价与信用分体系（v1 只展示在售/已售数量）

## 3. 用户角色

| 角色 | 描述 | 核心诉求 |
| --- | --- | --- |
| 买家（在校生） | 想低价买到教材、数码、宿舍用品 | 快速找到、能砍价、知道东西靠不靠谱 |
| 卖家（毕业生/换季学生） | 想把闲置处理掉 | 发布快、有人问、交易别扯皮 |

同一用户既是买家也是卖家，页面不区分角色，只在订单里区分「我是买家 / 我是卖家」。

## 4. 功能清单与优先级

| 模块 | 功能 | 优先级 |
| --- | --- | --- |
| 账号 | 注册登录、校园身份验证（学号）、个人主页（在售/已售） | P0 |
| 商品 | 发布、编辑、下架/上架、删除、图片上传 | P0 |
| 逛逛 | 分类、关键词搜索、价格排序、商品详情 | P0 |
| 私聊 | 文字/图片、报价卡片、交货信息卡片、收款码、支付凭证 | P0 |
| 收藏 | 收藏/取消、收藏列表、降价提醒 | P0 |
| 交易 | 下单、凭证确认、交货确认、双方确认完成、取消、超时取消 | P0 |
| 通知 | 降价提醒、订单状态变更 | P1 |
| 个人主页 | 他人主页（在售、已售，不展示评分） | P1 |

## 5. 核心流程

```
卖家发布商品（在售）
  ↓
买家浏览/搜索 → 详情页「聊一聊」
  ↓
议价：买家报价 → 卖家接受（也可还价/拒绝）
  ↓  接受即生成订单，商品 → 已预订
约定交货方式 / 地点 / 时间
  ↓
卖家发收款码 → 买家扫码转账 → 上传支付截图
  ↓
卖家「确认收款」→ 订单 → 待交货
  ↓
线下交货 → 双方各自「确认收货 / 确认交付」
  ↓  两人都确认
订单完成，商品 → 已售出
```

**异常分支**

- 预订后 15 分钟未付款 → 自动取消，商品回到在售
- 任一阶段双方可主动取消 → 商品回到在售
- 被预订期间商品不可再次下单

## 6. 状态定义

**商品**

| 状态 | 含义 | 可进入方式 |
| --- | --- | --- |
| 在售 | 可被浏览、议价、下单 | 发布、取消订单、重新上架 |
| 已预订 | 已有进行中的订单 | 卖家接受报价 |
| 已售出 | 交易完成 | 订单双方确认完成 |
| 已下架 | 卖家主动隐藏 | 卖家下架 |

**订单**

| 状态 | 谁该操作 | 出口 |
| --- | --- | --- |
| 待付款 | 买家（转账 + 上传凭证） | → 待确认收款；超时/取消 → 已取消 |
| 待确认收款 | 卖家（核对凭证） | → 待交货；取消 → 已取消 |
| 待交货 | 双方（线下交货 + 确认） | 双方都确认 → 已完成 |
| 已完成 | — | 终态 |
| 已取消 | — | 终态，商品回到在售 |

## 7. 页面清单

| 页面 | 主要内容 |
| --- | --- |
| 登录/注册 | 手机号 + 密码；注册可填学号完成校园认证 |
| 首页（逛逛） | 分类/搜索/排序 + 商品网格 |
| 商品详情 | 多图、价格、成色、卖家、交货方式、描述；收藏 + 聊一聊 |
| 发布/编辑 | 图片（≤4 张，首图封面）、标题、价格、分类、成色、交货方式、描述 |
| 消息 | 左：会话列表（含未读）；右：聊天 + 报价/收款码/凭证/订单卡片 |
| 订单详情 | 四步状态条、商品、交易信息、双方确认、支付凭证、时间线、操作区 |
| 我的 | 资料 + 统计；tab：我的商品（在售/已售/下架）、我的订单（买入/卖出） |
| 收藏 | 收藏列表，降价的标记原价差 |
| 通知 | 降价提醒、订单状态变更，可跳转对应订单/商品 |
| 收款码 | 上传/恢复默认收款码 |
| 他人主页 | 头像、认证、在售/已售数量、在售商品 |

## 8. 数据模型

```js
user    { id, nick, phone, pwd, school, campus, major, studentNo, verified, avatar, qrImage }
product { id, sellerId, title, price, origPrice, category, condition, desc, images[], delivery[], status, views, createdAt }
chat    { id, productId, buyerId, sellerId, messages[], lastTs, unread{userId:count} }
message { id, from, type, ...payload, ts }   // text | image | quote | delivery | qr | proof | order | system
order   { id, no, productId, chatId, buyerId, sellerId, amount, delivery, location, time,
          status, createdAt, expiresAt, buyerConfirmed, sellerConfirmed, proof, timeline[] }
notice  { id, userId, type, title, text, productId, orderId, ts, read }
```

## 9. 非功能需求

- **首屏**：启动时一次快照请求，之后页面渲染走本地缓存，切换页面无 loading
- **兼容**：Chrome / Edge / Safari 近两年版本；≥1280 四列、900 三列、≤720 两列
- **数据**：服务端 SQLite 持久化，换浏览器 / 重开服务数据不丢；提供一键重置（`npm run seed`）
- **安全**：口令 scrypt 加盐散列，接口 Bearer 令牌鉴权，越权操作返回 403
- **可访问性**：所有可点区域有可读文本或 aria-label；正文对比度 ≥ 4.5:1
- **体积**：前端资源 < 200KB（不含用户上传图片）

## 10. 验收标准（节选）

1. 未登录只能看到登录页；注册时填学号后主页显示「校园认证」
2. 首页分类、搜索、排序可组合使用，结果只含在售/已预订商品
3. 报价被接受后：商品变已预订、生成订单、聊天出现订单卡片，三者状态一致
4. 买家上传凭证后订单进入待确认收款，卖家收到通知
5. 仅一方确认收货时订单不完成；双方确认后商品变已售出
6. 预订超过 15 分钟未付款，订单自动取消且商品回到在售
7. 任一阶段取消订单，商品都回到在售
8. 卖家降价后，收藏过该商品的用户能收到降价通知
