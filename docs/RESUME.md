# 简历与面试怎么用这个项目

> 定位：一个**能跑起来、有数据库、有权限校验**的全栈小项目。比纯前端 Demo 强一档，关键在能不能讲清「为什么这么设计」。

---

## 一、真实数据（写简历别编）

| 指标 | 数值 |
| --- | --- |
| 形态 | 全栈单体：Node 服务 + SQLite + 原生 JS 前端 |
| 页面 | 7 个主页面 + 4 个衍页面 |
| 代码量 | 前端 ~2.8k 行、服务端 ~1.6k 行、样式 ~0.5k 行 |

## 二、三种写法

### 1. 一行版

> **校园二手交易平台**（个人项目 · Node + SQLite + 原生 JS）— 独立完成前后端，实现「发布 → 议价/直购 → 收款 → 交货 → 双方确认」完整闭环，49 条 API 集成测试保障。

### 2. 三条要点版（推荐）

> **校园跳蚤市场 · 二手交易平台** ｜ 个人项目 ｜ Node.js / SQLite / 原生 JS
>
> - 独立完成前后端：16 个 REST 接口 + 8 张表的 SQLite 数据模型，口令用 scrypt 加盐散列、Bearer 令牌鉴权，**业务规则全部收口在服务端**，越权操作一律 403
> - 把交易流程拆成**商品 4 态 + 订单 4 态双状态机**，覆盖取消、15 分钟超时释放两条异常分支；报价与「立即购买」两条通路共用同一套建单与锁货逻辑
> - 前端用**全量快照 + 版本号轮询**做同步渲染：页面零 loading，多标签页 4 秒内自动一致；49 条 API 集成测试接入 CI，覆盖鉴权、越权、重复下单等边界

### 3. 面试展开版（STAR）

- **S**：校内二手靠微信群，信息刷屏沉底、交易靠口头约定，容易因为「付了没 / 给了没」扯皮
- **T**：做一个只服务本校的二手站点，让「现在该谁操作」没有歧义
- **A**：
  1. 先定 8 条验收标准，再决定「服务端做唯一权威」，前端只负责展示
  2. 用双状态机描述交易，所有守卫写在 `domain.js`，前端按钮只是入口，不做安全边界
  3. 报价、收款码、支付凭证、交货信息做成**结构化消息卡片**，聊天记录本身即凭证
  4. 图片先在前端压缩再上传落盘，数据库只存 URL，避免快照膨胀
  5. 用临时数据库起真实服务跑集成测试，覆盖越权与状态冲突
- **R**：7 个页面全流程可跑通；49 条用例覆盖主流程与边界；零第三方依赖，`npm start` 即用

## 三、面试官大概率会问的 8 个问题

**Q1：为什么不用 Express / Koa？**
> 项目只有 16 个接口，Node 内置 http 足够；手写一层路由匹配反而让我能准确控制鉴权和错误码。如果接口上到几十个、要做中间件生态，我会换 Express 或 Fastify。

**Q2：为什么把业务规则放服务端？**
> 交易状态不能让客户端说了算。比如"确认收款"只有卖家能调，"确认收货"要按角色写对应标记——这些判断如果写在页面里，换个客户端就能绕开。服务端是唯一权威，前端按钮只是入口。

**Q3：订单和商品状态怎么保证不冲突？**
> 订单是主、商品跟随。接受报价或立即购买时把商品置为"已预订"并锁货；只有取消/超时才会回滚到"在售"，只有双方确认完成才会置为"已售出"。所有写入都在事务里，且每次都检查商品当前状态。

**Q4：双方确认收货怎么实现？**
> 订单上存 `buyer_confirmed` / `seller_confirmed` 两个标记，`confirmReceipt` 按调用者角色写其中一个，只有两个都为 1 才把订单置为完成、商品置为已售出。只点一方时订单停在"待交货"。

**Q5：前端为什么不用框架？**
> 7 个页面、状态集中在几个实体上，我更想要"渲染是纯函数、可断言"。页面只读内存快照，所以是同步渲染，没有 loading 态。要多人协作或长期迭代，我会换 React + TypeScript。

**Q6：多端同步怎么做的？**
> 每次写操作后服务端返回新快照，前端整体替换缓存；另外每 4 秒比对一次版本号，发现变化就重拉快照并刷新当前页。输入框聚焦时跳过刷新，避免打断打字。实时性要求高就该上 WebSocket。

**Q7：图片怎么存的？**
> 前端 canvas 等比压缩到最长边 900、JPEG 0.75，POST 给 `/api/upload`，服务端落盘到 `uploads/`，数据库只存 URL。如果不压缩、直接把 base64 塞进快照，每次同步都会传几百 KB。

**Q8：怎么保证质量？**
> `tests/api.spec.js` 用临时数据库起一个真实服务，用 fetch 跑完整流程：登录鉴权、发布校验、上传落盘、报价、重复报价拦截、凭证确认、双方确认、立即购买、取消回滚、越权编辑、无效令牌。49 条断言，CI 每次提交都跑。

## 四、别这么写（容易翻车）

| 雷区 | 说明 |
| --- | --- |
| 写「高并发」「百万级」 | 单机 SQLite 撑不起这种词，一问就露 |
| 把「零依赖」当唯一亮点 | 它是取舍，不是成就，要说清代价 |
| 只列技术栈 | 「Node/SQLite/JS」不像优势，像清单 |
| 不讲取舍 | 面试官最想听「你为什么不用 X」 |
| 没有可运行入口 | 简历上至少写清楚 `npm start` 后访问哪个地址 |
